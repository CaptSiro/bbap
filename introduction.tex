\section{Introduction}\label{sec:introduction}
Building a feature-complete full-stack framework requires a strong architectural foundation.
However, an emphasis on rapid feature implementation often leads to compromises in architectural design.
This contributes to the perception that the architectural complexity of modern frameworks often exceeds the requirements
of their intended functionality.

The goal of this thesis is to design and implement a full-stack web framework focused on ease of development,
extensibility, and AI-Generation tooling with minimal usage of third-party code.
The framework aims to define abstraction layers to combat the ever-increasing complexity of frameworks.
The intention is to make full-stack development faster and more straightforward.

\subsection{Tasks}\label{subsec:introduction-tasks}
To satisfy the goal, the thesis is divided into following tasks:

\begin{itemize}
    \item Research of state-of-the-art solutions.
    \item Study use cases and user stories.
    \item Design extensible full-stack framework architecture.
    \item Implement core full-stack framework components, including content rendering, routing, database model abstraction,
        multilingual support, and forms.
    \item Develop administrative system for managing user privileges and management of user-generated content.
        This includes managing user-defined web pages, files, localizations, and user privileges.
    \item Develop a component-based widget editor capable of creating, manipulating, and deleting widgets.
    \item Implement AI-Generation foundation capable of generating static webpages, widgets for the editor, translations,
        code documentation, article content generation, and website structure generation.
\end{itemize}

\subsection{Hypothesis}\label{subsec:introduction-hypothesis}
This thesis proposes multiple hypothesis:

\begin{itemize}
    \item Unified and convention-driven abstraction layers can streamline full-stack development.
    \item Implementing a framework without using third-party code requires more upfront effort but pays off when development
        of additional features is required.
    \item Achieving consistent architecture involves minimizing reliance on third-party libraries.
    \item AI generated content can decrease time in content creation, but the system is brittle and still has a learning curve.
\end{itemize}
