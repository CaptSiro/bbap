\subsection{Comparison of Existing Frameworks}\label{subsec:comparison-of-existing-frameworks}
This section compares two widely used web frameworks, Laravel and Nette.

\subsubsection{Laravel}\label{subsubsec:laravel}
Laravel~\parencite{laravel} is a modern open-source PHP web framework designed for developers and ease of development.
It provides built-in systems for routing, database connection, localization, and templating.
Laravel tackles developer productivity through expressive syntax and minimal boilerplate.

The primary advantages of Laravel include:

\begin{itemize}
    \item Clear MVC architecture.
    \item Built-in systems for common web development tasks.
    \item Strong documentation.
    \item Active community.
\end{itemize}

Laravel implements core features, but the focus on maintaining clean programming interface it constraints the features
in depth and flexibility.

For example the view implementation lacks type safety provided by using typed objects as interfaces for rendering views.
The calls to the built-in function view may be wrapped in another function and using the parameters of the function to achieve type safety.
This gives the developer option to either work in non-type-safe environment or to add unnecessary boilerplate to the application~\parencite{laravel_view}.

The routing system does not support compositional route definitions in which parent routes dynamically defines nested sub-routes.
This makes it difficult to encapsulate helper controller routes.
For example, route which handles reordering of priority-based table found in page listings.

The endpoints are stateless and are not aware of what path they are bound to.
Which means that routes need to be explicitly named to be able to programmatically retrieve them~\parencite{laravel_routing}.

Laravel does include library of useful view components,
but it does not include fully fledged out implementations of common page designs~\parencite{laravel_components}.
These designs include:

\begin{itemize}
    \item Home page.
    \item Article page.
    \item Listing page.
\end{itemize}

\subsubsection{Nette}\label{subsubsec:nette}
Nette~\parencite{nette} is an open-source PHP web framework focused on security, documentation, and clean application architecture.
The framework and documentation is tailored for developers in the Czech republic.
It provides a component-based structure built around the Model-View-Presenter (MVP) design pattern,
along with systems for routing, templating, and form handling.

The primary advantages of Nette include:

\begin{itemize}
    \item Demographic features for market in the Czech republic
    \item Focus on security
    \item OOP approach
\end{itemize}

Nette also defines system for testing code, but this approach requires to run the php source file directly from console
and does not provide output to HTML web page or writing reports to file~\parencite{nette_testing}.

File system for nette is utility class with defined functions for common operations with the native file system.
This system does not integrate extra functionality designed for web application.
Such as file upload, download, persisting file reference in database, or file structure abstraction~\parencite{nette_filesystem}.

\subsubsection{Frameworks Comparison Summary}\label{subsubsec:frameworks-comparison-summary}
Laravel emphasizes developer productivity and ease of development through its expressive syntax.
However, the simplicity in api results in limited depth for certain features,
such as lack of type safety in views and routing definitions not implementing dynamic structure and context aware endpoints.

Nette focuses on clean architecture, template security, and an object-oriented approach,
with strong support for developers in the Czech republic.
However, some subsystems are limited in scope,
functioning primarily as utility wrappers rather than full-featured systems designed for web applications.
This includes, for example, the file system abstraction.

Neither framework satisfies the design goals defined in this thesis, which include:

\begin{itemize}
    \item Strong type safety across all systems.
    \item Flexible and dynamic routing without reliance on static definitions.
    \item Fully fledged out integrated systems for common web application problems.
\end{itemize}

The thesis solution positions itself as an attempt to address found limitations by implementing strongly typed architecture
with deeper integration of system features.
